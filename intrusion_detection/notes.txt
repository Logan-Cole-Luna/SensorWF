Deployment steps

1. Copy four files into your STM32CubeIDE project (same folder as main.c):


firmware/stm32h7_can_ids_benchmark.c
firmware/stm32h7_can_ids_benchmark.h
models/trained_models/stm32h7_can_ids_float32.h   ← tree
models/trained_models/stm32h7_can_ids_scaler.h    ← scaler
2. Call init from main.c before osKernelStart():


#include "stm32h7_can_ids_benchmark.h"
// ...
ids_benchmark_task_init();
osKernelStart();
3. Wire UART — the benchmark task uses huart3 by default (the debug UART on most Nucleo-H7 boards). Change the IDS_UART define at the top of the .c file if yours differs.

4. Enable DWT in SystemInit() or early in main() (STM32CubeMX doesn't do this by default):


CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
5. Run the benchmark from your host machine:


# With hardware connected
python scripts/host_inference_runner.py --port /dev/tty.usbmodem14101

# Dry-run (no hardware, uses sklearn model)
python scripts/host_inference_runner.py --dry-run --samples 5000
Isolation mechanism — the firmware wraps every ids_predict() call with vTaskSuspendAll() / xTaskResumeAll(). The scheduler, CAN Rx ISRs, ADCS telemetry, and comms tasks are all frozen during the DWT measurement window. The only thing running is the tree traversal. UART Rx is briefly re-enabled between samples to receive the next feature vector, then locked out again before the inference starts.
